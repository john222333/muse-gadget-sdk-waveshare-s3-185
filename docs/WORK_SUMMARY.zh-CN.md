# 前期工作总结

## 1. 硬件移植

以原 Muse SDK 为基线，为 Waveshare ESP32-S3-LCD-1.85 无触摸板增加独立配置、板级驱动、工具识别和文档。检查厂家示例后落实 QSPI LCD、TCA9554 复位、背光、GPIO7 电源保持、BOOT/PWR 按键和两路 I2S。
将 LVGL 双缓冲高度从 32 行减至 12 行，保留 Wi-Fi/蓝牙所需内部内存。实测麦克风右声道有信号，配置 `mic_slot=1`。

旧程序在用户要求不备份的情况下清空；后续固件升级保留配网和配对 NVS。此公开仓库不包含任何原设备备份。

## 2. 配对和网络

通过 Muse 手机端蓝牙添加设备、配置 Wi-Fi，确认按住 BOOT 录音、松开发送。发现目标网络直连 Muse 失败，而电脑现有 HTTP 代理可访问。
实现可选电脑 TLS 转发及固件 DNS 包装：只匹配 Muse 域名，TCP 原样转发，保留 SNI 和 TLS 证书认证，不在电脑解密 Muse 链路。
独立路由器方案仅探索过，未作为完成品交付；不发布管理密码、路由器登录脚本或聊天凭据。

## 3. 在线女声

最初希望使用剪映甜美女声；讨论过字节语音服务，但没有 API 凭据。最终在用户同意把回复文字发送给微软后，改用 Edge 在线“晓伊”女声。未复制剪映音色，也不宣称晓伊就是剪映或“甜美小源”。
电脑完成短段语音合成，开发板解码 MP3 并重采样到 16 kHz 播放。合成任务与主会话隔离，使用代次/任务标识过滤被打断的旧结果。

## 4. 完整性和延迟修复

- 原版等待整条模型回复和整段 MP3；改为尽早划分首段、随后按标点分段。
- 修复首句结束后把整条消息提前标为完成的问题。
- 修复空行被单独合成、服务拒绝后后续不再朗读的问题。
- 修复服务可停顿约 10 秒、板子却 8 秒超时的冲突。
- 发现 WebSocket 在音频完成后还可等待 10 秒关闭确认；主机服务把关闭阶段限制为 0.1 秒，保持音频接收不变。
- 短段确认完整后再发送，未完成结果丢弃并最多重试一次；下一段可在当前段播放时预合成。
- 文字缓冲从 1 KB 经 4 KB 增至 32 KB；最终全文补齐流式尾部，空白/独立标点不生成语音。
- 给语音对话增加“先简短结论、普通问题少写长篇、详细请求仍完整回答”的指令。
- 末尾无关英文、UUID 和内部引用先清理；纯编号段返回 204，由板子跳过，正常英文名称、日期和数值保留。

## 5. 可复用交付

公开版包括板级移植、可配置主机语音服务、可选 TLS 转发、配置模板、安装/启动入口、测试、来源声明和中文指南。
本机绝对路径、家庭网络配置、SDK token、配对信息、原始对话日志、个人固件和试听文件都排除在公开发布之外。

## 0.2.0：通用烧录与手机音频（2026-10-09）

用户随后确认恢复服务后完整对话可用。提供空个人配置的四文件固件包、校验清单和独立 USB 配置工具，无需用户安装 ESP-IDF 或重新编译；首次替换可选择清空，升级可保留 NVS。SDK token、relay 地址、语音 URL/可选 Bearer key 和手机回复同步开关由用户在烧录后填写。

补上待机助手回复同步、音频引用解析、原始 MP3/PCM16 WAV 播放、下载失败后的文字 TTS 兜底和播放尾部等待队列。原始音频请求不附带用户语音 API key。新增配置、音频解析、烧录工具测试。实机本机模拟事件 MP3/WAV 已通过；真实手机 Muse 语音事件仍需复测，公开说明保留这一限制。公开固件采用社区原创头像，并附第三方许可。
